# geo-arg-audit（审计论证的独立性与判别力）

## 它做什么

回答判决回答不了的两个问题：这条论证实际上压在几条**独立**证据上，以及哪些检验**本来可能失败**。前者由 `geoarg independence` 给出有效证据数 `n_eff`，后者由 `geoarg hit-set` 给出“现在什么结果能撤回它”。技能的工作是解释这两个数，并指出那条决定性检验。

有转录级证据时，审计还要先读接地台账：`geoarg ground` 的验收率（`grounded / drafted`）与每条未接地引文的状态，决定这条论证的证据里有多少是真实写进源文件的。

## 什么时候会用到

- 用户问“这条论证有多硬”“这些证据真的独立吗”“该信多少”。
- 写综述或元分析，要把多篇文献合成一个置信度。
- 争论双方各执一词，需要判断分歧在数据、凭据还是独立性假设上。
- 选择研究方向：先算现有检验的判别力，再决定这场争论值不值得进。

## 常见问题

**n_eff 是精确值吗？** 不是。它是基于契约里独立性标注的估计，相关系数是先验表。报告时必须写 `n_eff / n` 和假设的平均相关系数，不能只写“有效证据 1.8 条”。

**判别力怎么判定？** 问一句：竞争假说下这个检验会给出不同结果吗？如果两种假说预测相同，判别力就是 `none`，即使检验通过也不构成支持。

**通过了的检验为什么不算支持？** 因为支持要求“检验本可以失败”。一个不可能失败的检验，通过与否不携带信息。

**和最小击穿集是什么关系？** `hit-set` 枚举的是单事件判废路径。多条降级判废条件同时成立也可能撤回论证，这种情况要在报告里显式说明，不能假定脚本已经找到。

**接地验收率算不算置信度的一部分？** 算，但它是另一个维度。`n_eff` 说的是证据有几条独立线，验收率说的是引文有几条确实存在。两个数都低，说明论证既单薄又可能编了引文；两个数都高也不代表结论对。

**报告默认是什么格式？** Word（`.docx`）。`geoarg report <case>` 写出 `<case>/report.docx`；只有需要逐行 diff 或终端查看时才用 `--format md` 输出 Markdown。报告框架（标题、字段名、表头）默认英文；`--lang zh` 切换为中文，契约内容本身按原文渲染。

**这个度量能直接发论文吗？** 可以，但需要语料与专家标注。这个技能给的是度量口径与报告格式，实证部分要自己补。

## 它生效的标志

- 报告以 Word 交付（`<case>/report.docx`），含 `n_eff / n`、平均相关系数、接地验收率与决定性检验。
- 报告里出现 `n_eff / n`、平均相关系数、以及每条警戒的解释。
- 报告里出现接地验收率，或明确说明没有转录级证据。
- 每条闸门检验都有一句“竞争假说会预测什么”。
- 报告点名了一条决定性检验，或明确说“目前没有”。
- 置信度段落单独拿出来也读得通，且用的是数字不是形容词。
