# geo-arg-audit（审计论证的独立性与判别力）

## 它做什么

回答判决回答不了的两个问题：这条论证实际上压在几条**独立**证据上，以及哪些检验**本来可能失败**。前者由 `geoarg independence` 给出有效证据数 `n_eff`，后者由 `geoarg hit-set` 给出“现在什么结果能撤回它”。技能的工作是解释这两个数，并指出那条决定性检验。

有转录级证据时，审计还要先读接地台账：`geoarg ground` 的验收率（`grounded / drafted`）与每条未接地引文的状态，决定这条论证的证据里有多少是真实写进源文件的。

## 什么时候会用到

- 用户问“这条论证有多硬”“这些证据真的独立吗”“该信多少”。
- 写综述或元分析，要把多篇文献合成一个置信度。
- 争论双方各执一词，需要判断分歧在数据、凭据还是独立性假设上。
- 选择研究方向：先算现有检验的判别力，再决定这场争论值不值得进。

## 常见问题

**n_eff 是精确值吗？** 不是。它是基于契约里独立性标注的估计，相关系数是先验表。报告时必须写 `n_eff / n` 和假设的平均相关系数，不能只写“有效证据 1.8 条”。

**判别力怎么判定？** 问一句：竞争假说下这个检验会给出不同结果吗？如果两种假说预测相同，判别力就是 `none`，即使检验通过也不构成支持；引擎会把“只有 `none` 级检验背书的满足状态”列为 `unbacked`。

**通过了的检验为什么不算支持？** 因为支持要求“检验本可以失败”。一个不可能失败的检验，通过与否不携带信息。

**和最小击穿集是什么关系？** `hit-set` 枚举的是单事件就能改变结论的结果。多条降级条件同时成立也可能撤回论证，这种情况要在报告里显式说明，不能假定脚本已经找到。

**cp 写着 holds，为什么判决还是不成立？** 因为满足状态要检验背书：cp 的 `holds`、判废条件的 `refuted`、蕴含的 `passed` 只有在对应检验 `passed` 且判别力不是 `none` 时才计数。否则引擎把它们列为 `unbacked`，判决停在 `UNDETERMINED`，`geoarg commit` 拒绝提交。

**接地验收率算不算置信度的一部分？** 算，但它是另一个维度。`n_eff` 说的是证据有几条独立线，验收率说的是引文有几条确实存在。两个数都低，说明论证既单薄又可能编了引文；两个数都高也不代表结论对。

**报告默认是什么格式？** Word（`.docx`）。`geoarg report <case>` 写出 `<case>/report.docx`；只有需要逐行 diff 或终端查看时才用 `--format md` 输出 Markdown。报告框架（标题、字段名、表头）默认英文；`--lang zh` 切换为中文，契约内容本身按原文渲染。报告默认写完整契约；只要一页时加 `--brief`。审查一份论文时通常出两份报告：论文所用语言一份（`--lang en` 或论文语言），运行模型的机器的系统语言一份（`--lang auto`），文件名建议 `report.<lang>.docx`。

**结论页和报告有什么区别？** 报告是完整的核对材料，结论页是按读者取舍的摘要。`geoarg card <case> --for researcher` 只给结论、缺少检验依据的项数、下一步检验、缺口与关键数字；`--for reviewer` 另加逐条理由、哪些结果会改变结论、证据独立性、引文核对表与审计信息。身份在会话开始时问一次即可，不写进契约，也不改变结论、`n_eff` 或验收率。

**领域和评述是什么？** `argument.yaml` 的 `profile` 只是元数据，在交付物页头标出论证所属领域，不选择术语、不改变用词。评述是模型撰写的 2–4 句文字（`--judgment` 或 `--judgment-file`），数字来自引擎，审计块记录规范化后文本的完整 sha256；`geoarg report` 接受同样的参数，`--brief` 也会带上评述。交付物里的条件、证据、推论一律引作者自己的陈述与普通语言，不另造术语；机器值只出现在台账与审计块里。

**这个度量能直接发论文吗？** 可以，但需要语料与专家标注。这个技能给的是度量口径与报告格式，实证部分要自己补。

**检验状态是手填还是算出来的？** 当检验记录了 `result` 和 `pass_rule` 时，引擎算出 `passed` / `failed` / `inconclusive`，算出的值优先于手填 `status`；`geoarg judge` 会对不一致报警。审计时看记录的值和规则，不要只看手填状态。改了 `result` 或 `pass_rule` 却没有重新 `commit`，`verify` 会报 `computed test statuses changed`。

**链路论证怎么审？** 有 `derived` 前提下先运行 `geoarg workspace <dir>`：确认每条链都解析、读目标论证的结论，并记下同一证据 id 是否在不同论证里内容不同。链只做相邻状态继承，不增加本论证的独立证据条数；目标论证的证据要在目标论证里审，不能重复计数。工作区报出引用找不到、成环或证据冲突时，先修这些再写审计结论。

**已提交的记录为什么会漂移？** `commit` 记录输入、引擎、判决和论证链摘要，`verify` 重算后逐项比对。改契约、换引擎版本、改判决或改论证链都会报出来；没提交过的案例只能看结构问题。工作区的漂移检查只覆盖有 `.geoarg/registry/` 的案例。

**审一页报告时，怎么知道它对应哪次提交？** 先跑 `geoarg verify <case>`。它除了输入和引擎漂移，还会检查记录的提交是不是台账里最新的一次、论证链有没有变、绑定的交付物有没有改：`deliverable changed since attestation` 说明手上这一份不是在提交记录上绑定的那一份，`registry record is not the latest commit` 说明后面又提交过。案例没有 attestation 时，把它当成“交付物未绑定”的缺口写进审计，而不是默认它和记录一致。

**台账和锚点可以当时间戳用吗？** 不可以。台账是案例目录内的哈希链，能发现就地改写，拦不住整体替换；`anchor.json` 只是台账头的一个检查点，只有被保管在案例目录之外时才对外部读者有意义。审计里只能写“在某个时间点存在过这个台账头”，不能写“第三方证明它在那个时间点存在”。

**多格式源文件怎么接地？** `geoarg ground <case> --source <paper>` 支持 PDF、DOCX、HTML、Markdown 和纯文本；页码只对 PDF 有意义，其余格式统一记为第 1 页。扫描 PDF 没有文本层时得到 `not-groundable`，需要先 OCR 或把记录降为解释级，不能靠肉眼补引文。

**论文组结论怎么算？** `geoarg bundle <dir>` 对 `bundle.yaml` 里每条主张运行 `judge`，必需主张按“成立 < 无法判定 < 未检验 < 被削弱 < 被推翻”取最弱一条。它是保守下界，不是概率合成，也不替代编辑对主张重要性的判断。

**提交台账能否改？** `commit` 向 `.geoarg/ledger.jsonl` 追加一行：每行带 `sha256`（本行正文的哈希），并有 `record_sha256` 与指向上一条 `sha256` 的 `prev`；`verify` 逐行校验自哈希、`prev` 和当前 registry 文件的摘要，能抓住「提交历史被悄悄改写」。但台账文件本身仍可整体替换，要防伪造，需要把摘要或锚点带到仓库外，用 `verify --anchor <file>` 对照。

## 它生效的标志

- 报告以 Word 交付（`<case>/report.docx`），含 `n_eff / n`、平均相关系数、接地验收率与决定性检验。
- 交付是一张结论页时，页头写明读者（研究者/评审者）与论证所属领域（若已声明），且页里的结论、`n_eff`、验收率与全量报告一致。
- 带了评述时，审计块里有该段落的 sha256，且正文没有把引擎模板句当评述用。
- 报告里出现 `n_eff / n`、平均相关系数、以及每条警戒的解释。
- 报告里出现接地验收率，或明确说明没有转录级证据。
- 有数值结果的检验，报告与台账用的是引擎算出的状态；手填状态与计算不一致时有明确提示。
- 论文有多条主张时，能看到 `bundle.yaml` 的组结论（必需主张里最弱一条）。
- 每条闸门检验都有一句“竞争假说会预测什么”。
- 报告点名了一条决定性检验，或明确说“目前没有”。
- 置信度段落单独拿出来也读得通，且用的是数字不是形容词。
